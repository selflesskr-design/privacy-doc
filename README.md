# Privacy (privacy.selfless.kr)

## 최근 접근성 개선

- 모바일 메뉴를 열면 키보드 초점이 메뉴 안으로 이동합니다. `Esc` 또는 닫기 버튼으로
  닫을 수 있고, 메뉴가 열린 동안 초점이 뒤쪽 화면으로 빠지지 않습니다.
- 메뉴를 닫으면 초점이 원래 메뉴 버튼으로 돌아오며, 메뉴·테마 버튼의 터치 영역을
  손가락으로 누르기 편한 크기로 키웠습니다.

## 최근 문구 개선

- 화면 읽기 기능에 남아 있던 영어 안내와 메뉴의 영어 분류명을 한국어로 바꿨습니다.
- `사진 크기`처럼 파일 용량과 가로세로 길이를 혼동하기 쉬운 표현을 구체적으로
  고치고, 조사와 문장 끝맺음이 어색한 공통 안내도 다듬었습니다.

## 최근 브랜드 개선

- 설치형 앱, iPhone 홈 화면, 공유 이미지와 결과 묶음 파일의 이름을 `Privacy`로
  통일했습니다. 기존 사용자의 설정과 오프라인 캐시를 지우지 않도록 내부 호환용
  `privacydoc:` 저장 키와 캐시 이름은 유지합니다.

**제출 전에 개인정보를 가리는 도구. 파일은 브라우저 안에서만 열립니다.**

계약서, 등본, 신분증 사본. 어딘가에 내야 하는데 주민등록번호나 계좌번호가 같이
적혀 있습니다. 처음 보는 변환 사이트에 올리면 그 파일이 어디에 남는지 알기
어렵습니다. 이 서비스는 파일을 서버로 보내지 않고 브라우저 안에서 처리합니다.

## 이 서비스가 하는 일

핵심은 **가리기** 두 개입니다. 나머지 도구는 그 주변을 채웁니다.

| | 하는 일 |
|---|---|
| **PDF 개인정보 가리기** | 가릴 영역을 픽셀에 직접 칠하고 새 PDF로 다시 만듭니다 |
| **사진 개인정보 가리기** | 같은 방식. 재인코딩 과정에서 EXIF(위치·기기·시각)도 함께 사라집니다 |
| **사진 위치정보 확인·삭제** | 확인 가능한 정보를 먼저 보여주고, 검사 결과와 관계없이 사진을 다시 저장해 숨은 정보까지 지웁니다 |

### 왜 사각형을 덮는 것으로는 안 되는가

PDF는 글자를 글자로 저장합니다. 그 위에 검은 사각형을 그려도 **아래 글자는
파일 안에 그대로 남아** 복사하면 나옵니다. 흔한 사고이고, 이 서비스가 존재하는
이유입니다. 그래서 `PDF 편집`(사각형을 얹는 도구)과 `PDF 개인정보 가리기`를
분명히 갈라두고, 편집 도구에는 그 한계를 경고로 띄웁니다.

가리기는 이렇게 동작합니다 ([src/lib/redact.js](src/lib/redact.js)):

1. 브라우저가 PDF 페이지를 캔버스에 그립니다
2. 가릴 영역을 **그 픽셀 위에 직접** 칠합니다
3. 칠해진 이미지만으로 PDF를 새로 만듭니다. 원래의 글자 데이터는 옮기지 않습니다

대가가 있습니다 — 저장한 PDF에서는 글자 선택과 검색이 안 됩니다. 가린 글자를
남기지 않기 위한 맞바꿈입니다.

## 파일이 나가지 않는다는 것을 어떻게 보장하나

**약속이 아니라 브라우저가 강제합니다.** [index.html](index.html)의
Content-Security-Policy가 통신 가능한 곳을 제한합니다. 나중에 누가 파일을
어딘가로 보내는 코드를 넣어도 브라우저가 거부합니다.

허용된 곳은 **우리 오리진과 구글 애널리틱스뿐**입니다. 애널리틱스로는 어떤
페이지가 열렸는지가 가고, 파일과 관련된 것은 아무것도 가지 않습니다 — 이름도,
크기도, 무엇을 넣었는지도.

- 폰트·아이콘·pdf.js 워커까지 전부 로컬 번들입니다. CDN이 없습니다
- [scripts/check-external-references.mjs](scripts/check-external-references.mjs)가
  소스의 외부 URL을 정적 검사하고, 허용 목록에 없으면 빌드를 실패시킵니다
- PWA라 첫 접속 이후에는 인터넷 없이도 동작합니다

PDF.js가 한글·CID 글꼴 PDF를 읽을 때 쓰는 CMap과 표준 글꼴도 서비스 워커에
미리 저장합니다. 사진 정보 삭제는 JPEG·PNG·WebP의 메타데이터 컨테이너를
확인하며, 화면에 표시할 정보가 없어도 정리 버튼을 제공합니다.

처리가 오래 걸리는 도구의 취소 버튼은 화면만 닫는 표시가 아닙니다. 이미지
압축에는 브라우저 취소 신호를 전달하고, PDF 변환은 진행 중인 페이지 렌더링을
멈춘 뒤 다음 페이지를 처리하지 않습니다.

**직접 확인하는 법**: 개발자도구 → 네트워크 탭을 열고 파일을 처리해 보세요.
또는 비행기 모드로 바꾸고 새로고침해 보세요. 그대로 됩니다.

`localStorage`에는 테마와 사이드바 상태만 남습니다.

## 시작하기

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # -> dist/ (프리렌더 + SEO 검사 포함)
npm run preview
```

Node 18+. 백엔드도 환경 변수도 없는 정적 사이트입니다.

## 도구 (17개)

### 개인정보 보호
PDF 개인정보 가리기 · 사진 개인정보 가리기 · 사진 위치정보 확인·삭제

### PDF (10개)
합치기 · 나누기 · 쪽 빼기·순서 바꾸기 · 쪽 번호 넣기 · 회전 · 편집 ·
워터마크 · 사진을 PDF로 · PDF를 사진으로 · 용량 줄이기

사이드바 순서는 **하는 일** 기준으로 묶여 있습니다 — 파일 단위 → 쪽 단위 →
얹기 → 다른 형식으로 → 용량.

### 사진 (6개)
용량 줄이기 · 크기 바꾸기 · 자르기 · 회전·뒤집기 · 워터마크 · 형식 바꾸기

### 알아둘 한계

- **한글을 PDF에 써넣으면 파일이 약 1.2MB 커집니다.** `@pdf-lib/fontkit`의
  서브셋 생성기가 일부 글리프를 빈 채로 써넣어(글자가 안 보임) 서브셋을 껐기
  때문입니다. 쪽 번호처럼 짧은 표기는 숫자·기호로 우회하고, 워터마크처럼 한글이
  꼭 필요한 곳은 `알아두실 점`으로 미리 알립니다. [src/lib/koreanFont.js](src/lib/koreanFont.js)
- **한글에는 굵게·기울임이 적용되지 않습니다.** Regular 한 벌만 싣습니다
- **암호가 걸린 PDF는 처리할 수 없습니다**
- **OCR이 없습니다.** 스캔 이미지로만 된 PDF에서는 글자를 찾지 못합니다

## 코드 구조

```
src/
  editors/       PdfRedactEditor · ImageRedactEditor   (레지스트리 밖의 독립 라우트)
  operations/    도구 하나당 폴더 — meta.js + index.jsx + helpers.js
  registry/      import.meta.glob으로 도구 자동 발견
  content/       pages.js(모든 페이지를 데이터로) · strings.js(모든 화면 문구)
  lib/           redact · imageRedact · exif · koreanFont · imageCanvas · pageSizes
  components/    Dropzone · AreaBox · ImageResult · SizeCompare · Sidebar …
scripts/         prerender.mjs · check-seo.mjs · check-external-references.mjs
```

**도구 추가는 폴더 하나면 됩니다.** 중앙 switch문이 없습니다.

**페이지도 데이터입니다.** [src/content/pages.js](src/content/pages.js) 하나가
라우팅·SEO 메타데이터·구조화 데이터·사이트맵·본문의 출처입니다. React 렌더러와
빌드 시 프리렌더러가 같은 정의를 읽으므로, 자바스크립트를 실행하지 않는
크롤러도 방문자와 같은 본문을 봅니다.

프리렌더된 도구 페이지의 관련 링크는 현재 존재하는 주소만 사용하며, 도구 개수는
레지스트리에서 자동으로 계산합니다. 도구를 추가하거나 제거해도 예전 숫자와 삭제된
주소가 검색엔진용 본문에 남지 않습니다.

별도의 자세한 설명 페이지가 있는 PDF 합치기·PDF 용량 줄이기·사진 위치정보
확인·삭제는 설명 페이지를 검색 대표 주소로 사용합니다. 실제 작업 화면은 그대로
쓸 수 있지만 검색 결과와 사이트맵에는 설명 페이지 하나만 노출합니다.

**화면 문구는 [src/content/strings.js](src/content/strings.js) 한 곳에** 모읍니다.
같은 동작을 두 이름으로 부르지 않기 위해서입니다.

**새 도구를 만들거나 고칠 때는 [docs/tool-ui-rules.md](docs/tool-ui-rules.md)를
먼저 읽으세요.** 도구마다 반복해서 나온 결함 세 가지가 적혀 있습니다.

### 기술 스택

React 18 · Vite 5 · Tailwind 3 · vite-plugin-pwa

사용자 브라우저로 나가는 라이브러리는 여덟 개입니다 — `pdf-lib`, `pdfjs-dist`,
`@pdf-lib/fontkit`, `react`, `react-dom`, `browser-image-compression`, `fflate`,
`jspdf`. 빌드 도구(Vite, Tailwind, PostCSS)는 사용자에게 나가지 않습니다.

빌드하면 이 라이브러리들의 코드가 우리 번들 안으로 들어옵니다. 실행 중에 npm이나
GitHub에 접속하지 않습니다.

## 배포

`main`에 push하면 Vercel이 자동 배포합니다. `npm run build`는 프리렌더와 SEO
검사를 함께 돌리고, 검사가 실패하면 배포가 멈춥니다.

없는 주소는 `dist/404.html`로 **진짜 404**를 반환합니다. catch-all 리라이트가
없어야 동작하므로 [vercel.json](vercel.json)에 두지 않았습니다.
