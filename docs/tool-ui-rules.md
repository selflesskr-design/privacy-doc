# 도구 화면 규칙

같은 결함이 도구마다 반복해서 나왔습니다. 새 도구를 만들거나 기존 도구를
고칠 때 이 세 가지를 먼저 확인하세요.

## 1. 설정이 바뀌면 만들어둔 결과를 버린다

만든 뒤에 설정·파일 목록·영역을 건드리면 `job.reset()`을 부릅니다.

그러지 않으면 화면에는 새 설정이 보이는데 받기 버튼은 옛 파일을 쥐고 있습니다.
오류도 안 나고 버튼 모양도 그대로라, 받은 파일을 열어보지 않으면 모릅니다.

실제로 있었던 일:

- `PDF 합치기` — 순서를 바꿔도 바꾸기 전 순서로 합쳐진 파일이 내려갔습니다.
- `사진을 PDF로` — A4로 만들고 A5로 바꿔도 A4 파일이 내려갔습니다.
- `PDF 개인정보 가리기` — 저장한 뒤 영역을 더 그려도, 그 영역이 없는 파일이
  내려갔습니다. 가리기 도구에서 이건 개인정보가 새는 것과 같습니다.

## 2. 버튼은 한 번에 하나만 보인다

결과가 없으면 **만들기**, 결과가 있으면 **받기**. 둘을 나란히 두지 않습니다.

나란히 두면 눌렀는지 알 수 없고, 받기 버튼이 두 곳에 생기기도 합니다.
1번 규칙을 지키면 설정을 건드리는 순간 만들기 버튼이 저절로 돌아옵니다.

## 3. 화면 문구는 한국어로, `src/content/strings.js`에 모은다

- 도구 안에 영어를 남기지 않습니다. 툴팁, 진행 문구, 오류 제목까지 포함입니다.
- 같은 동작은 같은 말로 부릅니다. `COMMON`에 있는 것을 먼저 찾아 쓰세요.
- 안내(`meta.js`의 `notes`)는 개조식으로. 배열로 주면 항목별로 나옵니다.
- 구구절절 쓰지 않습니다. 그 시점에 필요한 것만 — 왜 그런지 한마디, 다음에
  뭘 누를지 한마디.

## 그 밖에

- **한글을 PDF에 써넣으면 파일이 1.2MB 커집니다.** 한글 글꼴을 통째로 싣기
  때문입니다(`src/lib/koreanFont.js`). 쪽 번호처럼 짧은 표기는 숫자·기호로
  우회하고, 워터마크처럼 한글이 꼭 필요하면 `notes`로 미리 알립니다.
- **설정이 여러 개 얽힌 도구에는 미리보기를 넣습니다.** `usePdfThumbnail`이
  `{ url, widthPt, heightPt }`를 돌려주므로 PDF 좌표 그대로 SVG를 얹으면
  됩니다. `PDF 워터마크`와 `쪽 번호 넣기`를 참고하세요.
- **사진을 다루면 EXIF 방향을 적용합니다.** 휴대폰 세로 사진은 가로 픽셀로
  저장되고 방향 태그가 따로 붙습니다. `lib/imageCanvas.js`의 `decode()`를
  쓰거나, 직접 디코딩한다면 `imageOrientation: 'from-image'`를 넘기세요.
